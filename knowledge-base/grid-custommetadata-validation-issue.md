## Description

Models generated by Entity Framework scaffolding are overwritten when they are regenerated. To keep validation attributes outside the generated files, you can associate a partial model class with a separate metadata class through the [MetadataTypeAttribute](https://learn.microsoft.com/dotnet/api/system.componentmodel.dataannotations.metadatatypeattribute).

By itself, however, `MetadataTypeAttribute` is not automatically used by modern .NET data-annotations validation. As a result, validation attributes from the metadata class are not honored by either a standard Blazor `EditForm` or the Telerik Grid.

## Cause

The behavior is not caused by the Grid creating model instances through `Activator.CreateInstance()`. Metadata providers are registered for a type and apply to all instances of that type, including instances created through `Activator.CreateInstance()`.

The Grid uses Blazor's `EditContext` and data-annotations validation. Unless an `AssociatedMetadataTypeTypeDescriptionProvider` is registered for the model type, .NET validation does not inspect the associated metadata class.

## Solution

Register an `AssociatedMetadataTypeTypeDescriptionProvider` once, before the model is validated. Registration can take place during application startup or in a static constructor on the partial model class.

The following example keeps all validation attributes outside the scaffolded file.

````C#
using System.ComponentModel;
using System.ComponentModel.DataAnnotations;

[MetadataType(typeof(CustomerMetadata))]
public partial class Customer
{
    static Customer()
    {
        TypeDescriptor.AddProviderTransparent(
            new AssociatedMetadataTypeTypeDescriptionProvider(typeof(Customer)),
            typeof(Customer));
    }
}

public class CustomerMetadata
{
    [Required(ErrorMessage = "Title is required.")]
    public string? Title { get; set; }
}
````

The scaffolded part remains free of manually maintained attributes:

````C#
public partial class Customer
{
    public string? Title { get; set; }
}
````

The static constructor runs before the first `Customer` instance is created. After registration, standard Blazor data-annotations validation and the Telerik Grid honor the attributes from `CustomerMetadata`. This applies to instances created directly and to instances created by the Grid.

Alternatively, register the provider during application startup:

````C#
TypeDescriptor.AddProviderTransparent(
    new AssociatedMetadataTypeTypeDescriptionProvider(typeof(Customer)),
    typeof(Customer));
````

When the metadata type is supplied explicitly to the provider, the `MetadataTypeAttribute` is optional:

````C#
TypeDescriptor.AddProviderTransparent(
    new AssociatedMetadataTypeTypeDescriptionProvider(
        typeof(Customer),
        typeof(CustomerMetadata)),
    typeof(Customer));
````

Call the registration only once per model type and before rendering or validating a form that uses the model.

>caption Custom validation attributes

When a custom `ValidationAttribute` returns a validation error, include `validationContext.MemberName` in the `ValidationResult`. This allows model validation during Grid submission to associate the error with the correct editor:

````C#
protected override ValidationResult? IsValid(
    object? value,
    ValidationContext validationContext)
{
    if (value is null)
    {
        return new ValidationResult(
            ErrorMessage,
            [validationContext.MemberName!]);
    }

    return ValidationResult.Success;
}
````

Without the member name, submission can still be blocked, but the error is associated with the model instead of the field. As a result, the corresponding editor may not display its validation tooltip or invalid styling.
